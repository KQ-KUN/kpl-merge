请开始开发 KPL GAME 新小游戏：

中文名：合成KPL
英文名：KPL Merge
建议仓库：KQ-KUN/kpl-merge
未来正式路径：/merge/

这是一个受 Suika / 合成大西瓜类玩法启发的纯前端物理合成小游戏。

但不是简单换皮。

本游戏的核心差异机制是：

“玩家先选择自己的本命战队，最终最高级球固定为本命战队；本局其他中间队徽随机排列。”

例如：
AG 粉丝选择成都AG超玩会，
最终最高等级永远是 AG。

狼队粉丝选择重庆狼队，
最终最高等级永远是狼队。

中间队徽每局随机，因此每局都有不同的“合成本命路线”。

==================================================
5. 核心等级系统
==================================================

V1 固定为 8 个物理等级：

Level 0
Level 1
Level 2
Level 3
Level 4
Level 5
Level 6
Level 7

其中：

Level 7 = 玩家选择的本命战队

Level 0～6 =
从其他符合条件的战队中随机抽取 7 支不同战队。

本命战队绝对不能出现在 Level 0～6。

例如本命 AG：

本局可能生成：

L0 KSG
L1 Hero
L2 DYG
L3 DRG
L4 eStar
L5 WB
L6 狼队
L7 AG

下一局可能变成：

L0 WE
L1 TTG
L2 狼队
L3 KSG
L4 WB
L5 DRG
L6 eStar
L7 AG

要求：

- 中间顺序每局随机
- 同一局生成后立即锁定
- 游戏中途绝不能重新随机
- 使用 Fisher-Yates 或等价无偏 shuffle
- RNG 应允许测试注入
- 不允许同一战队占两个等级

==================================================
6. 必须显示免责声明
==================================================

因为等级顺序随机，必须明确显示一句：

“本局中间队徽随机排列，仅代表球体等级，不代表战队实力、排名或历史成绩。”

不要设计成：

弱队 → 强队

不要根据冠军数、排名、热度决定等级。

这是随机路线。

==================================================
7. 合成规则
==================================================

标准 Suika 规则：

两个相同等级的球发生有效碰撞：

Level N + Level N
→ Level N+1

例如：

L0 + L0 → L1
L1 + L1 → L2
……
L6 + L6 → L7 本命战队

只有：

等级完全相同

才能合并。

不同等级永不合并。

一次碰撞只能结算一次，
必须防止 Matter.js 同一碰撞在相邻 tick 中被重复合成。

新生成球的位置取两球合理中心位置。

保留动量/轻微弹性，
但优先保证手感稳定而不是严格物理真实性。

==================================================
8. 最终本命球
==================================================

Level 7 是终极本命球。

L6 + L6 → Level 7

产生本命球时：

- +5408 分
- 触发明显庆祝反馈
- 显示：
  “本命达成！”
- 显示本命战队名称和队徽
- 有短暂放大 / 光圈 / 粒子 / 震动反馈
- 支持 reduced-motion
- 手机若支持，可用极轻微 navigator.vibrate，但失败必须静默

重点：

生成一个本命球后游戏不结束。

玩家可以继续玩，
争取：

- 更高分
- 第二个本命
- 第三个本命

两个 Level 7 本命球：

不能继续合并。

不要创造 Level 8。

Level 7 留在场上成为大型物理障碍。

==================================================
9. 精确计分规则
==================================================

这是确定规则，不允许擅自修改。

自然掉落：
0 分

只有“成功发生合成”才加分。

计分根据“合成后的等级”：

L0 + L0 → L1
+6

L1 + L1 → L2
+26

L2 + L2 → L3
+32

L3 + L3 → L4
+219

L4 + L4 → L5
+335

L5 + L5 → L6
+606

L6 + L6 → L7（本命）
+5408

建立唯一配置，例如：

MERGE_SCORES = {
  1: 6,
  2: 26,
  3: 32,
  4: 219,
  5: 335,
  6: 606,
  7: 5408
}

不要把这些数字分散硬编码。

不要“优化”成连续数学序列。

这些就是产品规则。

==================================================
10. 连锁合成计分
==================================================

连锁合成逐级结算。

例如：

L1 + L1
→ L2
→ +26

新 L2 立即碰上另一个 L2：

L2 + L2
→ L3
→ +32

这一波总计：

+26
+32

两个加分动画都应出现。

如果继续连锁：

+219
+335
……

每一次实际 merge 独立计分。

==================================================

Level 1：35%
Level 2：15%

以后方便调平衡。

绝不能自然生成：

L3～L7。

本命球只能靠合成获得。

Next Preview 必须显示下一球：

队徽
等级/尺寸视觉

==================================================
12. 球体视觉
==================================================

Matter.js 碰撞体保持圆形。

因为 KPL 队徽形状不同，
不要直接让透明 Logo 边缘看起来像碰撞边缘。

每个球统一设计成：

圆形底板
+ 内部居中的战队队徽

要求：

- logo 使用 contain
- 保留安全 padding
- 不拉伸
- 不裁掉核心图形
- 小球也能辨识
- 不同 logo 的视觉面积尽量一致

等级越高：

物理半径越大。

不要根据战队本身改变尺寸。

Level 7 可以有一圈特殊本命光环，
但不得改变真实碰撞半径。

==================================================
17. 游戏结束
==================================================

不要只要球瞬间弹过危险线就 Game Over。

避免误判。

规则：

只有已经释放、处于物理世界中的球，
在危险线以上持续稳定超过指定时间，
才触发结束。

建议先从：

约 1.5～2 秒

开始调试。

当前正在投放的 preview ball 不参与判断。

发生连锁爆炸/弹跳时要有 grace period。

Game Over 后：

暂停新增球，
但可以让物理世界短暂稳定后展示结果。
